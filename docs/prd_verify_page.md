# PRD 草稿：“核验”页（免 key，不调用任何模型）

> 状态：草稿，2026-10-06。这是第 4 阶段网页 PRD 中的一个页面，等第 4 阶段任务原文到位后再合并进完整 PRD 和原型。
> 依赖：“通用提示词”明天做，它决定了 AI 结果的标准格式（§4）。本页先按现有流水线的抽取格式来设计，提示词定稿后再对齐。

## 1. 目的

用户已经让别的 AI（ChatGPT、Claude、Gemini、DeepSeek 等）按我们的通用提示词读过一份财报，想知道哪些数靠不住。本页用现有核验层做**纯代码**检查，把可疑项标红并说明原因。

- 不需要 API key。
- 不调用任何模型，包括解析用户粘贴的结果，也用代码完成。
- 财报 PDF 和 AI 结果都不会发给任何模型服务商。

## 2. 输入

| 输入 | 必填 | 说明 |
|---|---|---|
| 财报 PDF | 是 | 用户上传。用现有解析（`parse.pdf_pages`：pdfplumber + NFKC）按页取文字 |
| AI 结果 | 是 | 粘贴文本，可以是 JSON 或表格（Markdown 表格、从网页复制的制表符分隔表格）。格式见 §4 |
| 市场 | 是 | 美股 / A 股 / 港股。决定币种默认规则（例如 A 股单独的“元” = 人民币）和能否做 C4 |
| 报告期 | 是 | 例如 2026H1、2026Q3、2026FY。用来确定目标期末，判断 AI 给的是不是本期数、是单季还是累计 |
| 股票代码 | 否 | 美股和 A 股填了才有可能做 C4（§3） |
| 行业模板 | 否 | 通用 / 银行 / 保险。默认按现有规则从利润表结构自动判定（`templates.choose_template`），用户可以改 |

## 3. 检查（全部复用现有核验层，不另写规则）

| 检查 | 做什么 | 本页的条件 |
|---|---|---|
| C1 引用在页上 | AI 给的原文引用能否在它说的那一页（±1 页）找到 | AI 结果里要有页码和引用。没有的话，C1 记为“无出处，无法核验”（标红） |
| C2 数字在页上 | 数字本身是否逐字出现在那一页 | 没给页码时，在全文搜这个数，列出它出现在哪几页；仍按“无出处”标红 |
| C3 单位 / 币种 | 单位和币种能否解析、每股指标倍数是否为 1、仙 / 美分按 0.01 换算（R2、R6） | 总是做 |
| 合理性检查 S1–S5 | 毛利 ≤ 营收、归母 ≥ 普通股、推导值 = 明示值、EPS × 股数 ≈ 净利润、单季 + 上季累计 ≈ 累计 | 某项检查需要的数都有时才做。S5 的“上季累计”要取结构化数据，只在能取到时做（同 C4 条件） |
| C4 结构化数据比对 | 和 SEC XBRL（美股）/ 东财（A 股）的数比对 | **仅美股和 A 股**，并且填了代码、能取到这一期的结构化数据时才做。美股要先用代码 + 报告期找到对应的申报（`sources.fetch_us(download=False)`），找不到就跳过。**港股不做 C4**：东财港股数据可能换算过币种，不可靠 |
| 期间判定 / 漏抽 | 报告期应有的字段和期间（例如中报的单季列），AI 没给的列为“缺失” | 用现有 `expected_pairs` 规则 |

结果状态和单家分析页一致：

- ✅：C1–C3 通过，且与结构化数据一致；
- ⚠️：C1–C3 通过，但没有可比对的结构化数据；
- ❌：任一检查失败，标红。

❌ 的分类沿用现有的：数字编造、引用改写、页码错、单位、口径/推导、期间、漏抽、解析问题。新增一类“无出处”：AI 没给页码或引用。

## 4. AI 结果的格式（待通用提示词定稿）

- **JSON**：按流水线抽取格式，即 `items[]`，每项包含 `field`、`raw_value`、`raw_unit`、`raw_currency`、`period_type`、`period_end`、`page`、`quote`。有推导项时再加 `derivation` 和 `components`。通用提示词会要求 AI 输出这个格式。
- **表格**：用代码按表头识别列，至少要有指标、数值、单位、期间；页码、原文两列可选。识别不了的列名，提示用户手动对应各列，不调用模型。
- 先做格式校验，再做核验。字段名不认识、数值不是数字、期间写不清楚的行，单独列为“无法解析”，并标明是哪一行。这些行不参与核验，也不会被悄悄丢掉。

## 5. 输出

- 结果表与单家分析页同一个组件。
  - 列：指标、期间、数值（原文写法 + 换算后）、币种、状态、页码、原因。
  - 可疑项标红。点“原因”展开，列出失败的检查和证据：原文那一页的相关行、找到的页码、结构化数据的值和来源。
- 表头写明本次做了哪些检查。例如“C1–C3 + 合理性检查；未做 C4（港股无可靠结构化数据）”，或“未做 C4（未填代码）”。
- 可导出 CSV / JSON。

## 6. 页面上必须写明的限制（文案约束）

- 核验只能说明“这个数在原文里、单位对、和其他数自洽”，**不能说明它就是要找的那个指标**。例如把经营利润当毛利、把保险收入当总收入，本页抓不到。（评估：人工标“原文没有”的 12 项中，流水线给出数字 3 次，一次也没被标出。）
- 未标红不等于正确。评估中标记召回率港股明显低于美股 + A 股：港股没有可靠的结构化数据可比对，C4 不起作用。具体数字引用方法与评估页，两组分开写。
- **禁止**出现“零静默错误”“全部错误都会被标出”“已验证无误”这类说法。✅ 的文案写“通过核验”，不写“正确”。
- 扫描版 PDF（取不到文字）没法核验，直接提示，不出结果表。

## 7. 不做

- 不调用任何模型（解析、纠错、补全都不做）。
- 不替用户“修正”数字，只标出问题和证据。
- 不保存用户上传的 PDF 和粘贴内容（处理完即丢）。如果需要缓存，另行确认。

## 8. 原型里要留出的位置

- 导航新增“核验”。
- 上传区（PDF）+ 粘贴区（AI 结果）+ 市场 / 报告期 / 代码 / 模板四个选项 + “开始核验”按钮。
- 粘贴区旁放“通用提示词”的入口，先放占位：“明天提供”。
- 结果区复用单家分析页的结果表，表头上方一行写明本次做了哪些检查。
- 页脚固定显示 §6 的限制文案。
